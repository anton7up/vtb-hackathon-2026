# АнтиСкам — VTB Hackathon 2026

Учебный банковский антифрод-прототип с кабинетами клиента и сотрудника банка. Система проверяет переводы обученной ML-моделью, анализирует подозрительные ссылки и QR-коды, ведёт серверную историю операций и подключает ИИ-помощника Groq для дополнительного опроса клиента.

> Все пользователи, счета, получатели, деньги и инциденты вымышлены. Проект не подключён к ВТБ, платёжным системам или закрытым банковским базам и не предназначен для реальных операций.

## Возможности

- роли клиента и сотрудника банка с серверной авторизацией и HttpOnly-сессиями;
- переводы с отдельным подтверждением и классами `normal`, `review`, `block`;
- обученная Python-модель фрода: 13 признаков, сохранённые пороги и аудит результата;
- очередь переводов на дополнительной проверке и решение сотрудника;
- ИИ-опрос клиента через Groq/Qwen без права самостоятельно разрешить платёж;
- SQLite-история `transfer_ledger`, включая снимок признаков и версию модели;
- проверка URL локальной ML-моделью, безопасный статический анализ HTML и открытый список Банка России;
- разбор QR-кодов и безопасный учебный переход QR → получатель → проверка перевода;
- жалобы на получателей, общий реестр риска и защита нескольких демо-клиентов;
- доверенные лица, лимиты, 24-часовая защитная пауза и сценарий «Это был не я»;
- адаптивный интерфейс в стиле банковского кабинета.

## Архитектура

```text
Браузер клиента/сотрудника
          │ HTTPS / JSON
          ▼
Node.js API и интерфейс :3000
    ├── SQLite: аккаунты, состояния, transfer_ledger, реестр
    ├── локальная URL-модель и безопасный HTML-сканер
    ├── Python ML-сервис переводов :8101 (только loopback)
    └── Groq/Qwen или отдельный HTTPS relay
```

Основной самостоятельный режим запускается через `server/index.mjs`. Cloudflare/Sites-режим сохранён в репозитории отдельно, но для локального запуска и VPS не требуется.

## ML-классификация переводов

Готовая модель находится в `pipeline/artifacts/fraud_model.joblib`, HTTP-обёртка — в `pipeline/service.py`. Переобучение для запуска не требуется.

Модель получает текущую операцию и прошлые операции из `transfer_ledger`, после чего рассчитывает 13 признаков:

```text
hour, dow, night, amount, sender_balance, amount_ratio,
is_new_payee, payee_tx_before, days_since_first_payee,
sender_tx_before, amount_to_avg, receiver_tx_before, is_round
```

Результаты:

| Код | Класс | Действие |
|---:|---|---|
| `0` | `normal` | можно перейти к отдельному подтверждению |
| `1` | `review` | деньги не списываются, операция передаётся сотруднику и доступен ИИ-опрос |
| `2` | `block` | перевод останавливается до списания |

Если настроенный Python-сервис не отвечает или возвращает неверный контракт, перевод не разрешается автоматически. Вероятность, пороги, версия модели и снимок всех признаков сохраняются для аудита.

В интерфейсе есть 15 воспроизводимых ML-сценариев — по пять на каждый класс. Их учебный контекст не меняется после повторных показов, но введённая сумма остаётся настоящим входным признаком. Отдельная группа «Из истории БД» использует живые агрегированные данные `transfer_ledger` и поэтому может меняться после новых операций.

Подробнее: [классификация переводов](docs/transfer-classification.md) и [описание pipeline](pipeline/README.md).

## Быстрый запуск полной версии

Требования:

- Node.js `22.13+`;
- Python `3.14.4` для точного соответствия зафиксированным версиям ML-библиотек;
- установленный Chrome, Edge или Chromium для живого статического анализа страниц;
- ключ Groq — только если нужен ИИ-помощник.

### 1. Установить Node.js-зависимости

```powershell
npm ci --ignore-scripts
```

### 2. Подготовить Python-окружение

Windows PowerShell:

```powershell
py -m venv .venv-ml
.\.venv-ml\Scripts\python -m pip install -r pipeline\requirements.txt
```

Linux:

```bash
python3 -m venv .venv-ml
./.venv-ml/bin/python -m pip install -r pipeline/requirements.txt
```

### 3. Создать локальный `.env`

```dotenv
HOST=127.0.0.1
PORT=3000
DATABASE_PATH=data/antiscam.sqlite
TRANSFER_MODEL_URL=http://127.0.0.1:8101/v1/classify

# Необязательно: ИИ-помощник
GROQ_API_KEY=

# Необязательно: шлюз, если с сервера нет прямого доступа к Groq
# GROQ_API_URL=https://your-relay.example/api/groq
# GROQ_RELAY_TOKEN=replace-with-independent-secret

# Необязательно: режим сканера без установленного браузера
# SCANNER_LOADER=static
```

Файлы `.env*`, SQLite и ключи исключены из Git. Не добавляйте реальные секреты в исходники или клиентский код.

### 4. Запустить ML-сервис

Windows:

```powershell
.\.venv-ml\Scripts\python pipeline\service.py
```

Linux:

```bash
./.venv-ml/bin/python pipeline/service.py
```

Сервис слушает `127.0.0.1:8101`; этот порт нельзя публиковать в интернет.

### 5. Запустить сайт

Во втором терминале:

```powershell
npm start
```

Открыть `http://127.0.0.1:3000`. База и таблицы создаются автоматически. Для разработки с перезапуском используется `npm run dev`.

Без `GROQ_API_KEY` сайт, БД, переводы, ML-классификация, URL-модель и QR-проверка продолжают работать; недоступен только внешний ИИ-диалог. Без `TRANSFER_MODEL_URL` интерфейс честно показывает резервный демонстрационный классификатор, а не обученную модель.

## Учебные аккаунты

| Роль | Логин | Пароль |
|---|---|---|
| Клиент | `client` | `ClientDemo2026!` |
| Сотрудник банка | `employee` | `BankDemo2026!` |

Дополнительные клиенты `client2` и `client3` используются для сценариев общей истории, жалоб и доверенных лиц; их пароли передаются команде отдельно. В БД и исходниках хранятся только соль и PBKDF2-SHA256-хеши паролей.

## Короткий сценарий для демонстрации

1. Войти как `client` и открыть раздел переводов.
2. Выбрать «Мама (обычный перевод)», 500 ₽ — модель возвращает `normal`.
3. Выбрать «Алексей Орлов (ML: доп. проверка + ИИ)», 3 250 ₽ — результат `review`, операция появляется в «Безопасности» и доступен ИИ-опрос.
4. Выбрать «Фишинговый получатель (ML: блокировка)», 50 000 ₽ — результат `block`, списания нет.
5. Открыть группу «Из истории БД» и показать число операций, отправителей и среднюю сумму, рассчитанные из `transfer_ledger`.
6. Войти как `employee`, открыть очередь проверки, изучить признаки/источник решения и принять решение по операции.

Важно: сумма не определяет класс в одиночку. Например, 50 000 ₽ знакомому получателю могут получить `normal`, а та же сумма новому получателю вместе с другими признаками — `block`.

## Размещение на VPS

Для постоянной версии рекомендуется:

- Node.js-сервис и Python ML-сервис запускать отдельными `systemd` units;
- слушать Node только на `127.0.0.1:3000`, ML — только на `127.0.0.1:8101`;
- публиковать сайт через Nginx/Caddy с HTTPS;
- хранить SQLite на постоянном диске вне каталога Git;
- хранить Groq/relay-секреты только в окружении сервиса;
- делать согласованные резервные копии SQLite;
- перед обновлением кода сохранять резервную копию БД.

Пример серверного окружения:

```dotenv
HOST=127.0.0.1
PORT=3000
PUBLIC_ORIGIN=https://your-domain.example
DATABASE_PATH=/var/lib/antiscam/antiscam.sqlite
TRANSFER_MODEL_URL=http://127.0.0.1:8101/v1/classify
GROQ_API_KEY=replace-on-server
```

SQLite подходит для одной серверной реплики. Для горизонтального масштабирования потребуется отдельная СУБД и пересмотр механизма блокировок/транзакций. Подробности: [локальный запуск и перенос](docs/local-server.md).

## Структура репозитория

| Путь | Назначение |
|---|---|
| `server/` | самостоятельный Node.js HTTP-сервер и безопасный сканер страниц |
| `lib/` | банковское API, авторизация, правила защиты и интеграции |
| `public/` | интерфейс клиента и сотрудника |
| `drizzle/` | последовательные SQLite-миграции |
| `pipeline/` | обученная модель переводов, признаки, сервис и отчёт |
| `synthetic/` | синтетические данные для обучения транзакционной модели |
| `pipeline_legal/`, `synthetic_legal/` | материалы отдельного юридического pipeline |
| `groq-relay/` | ограниченный HTTPS-шлюз к Groq для сервера без прямого доступа |
| `docs/` | архитектура, ограничения и сценарии проверки |
| `tests/` | автоматические тесты API, моделей, UI-контрактов и безопасности |
| `app/`, `worker/` | сохранённый облачный режим |
