
# АнтиСкам

Локальная система для хакатона: самостоятельный Node.js-сервер, SQLite-файл, вход по логину и паролю и две роли. Облачный режим Cloudflare D1 сохранён отдельно, но для локального запуска не нужен.

## Аккаунты и права

Четыре аккаунта создаются в таблице `accounts` при инициализации: `client`, `client2` и `client3` с ролью клиента, `employee` с ролью сотрудника. Ролей по-прежнему две. У клиентов отдельные баланс, история, пауза, жалобы и настройки доверенных лиц; реестр получателей общий. Пароли переданы владельцу в чате. В исходниках и базе хранятся только соль и PBKDF2 SHA256 хеши с 100 000 итерациями. При добавлении новых клиентов существующие данные не сбрасываются.

- `/login` — вход без выбора роли.
- `/client` — переводы, наличные, данные доступа, личная история и обращения.
- `/employee` — решения системы, реестр, журнал событий и ответы на обращения.
- Роль задаёт запись в БД. Параметры URL не меняют её. Чужой кабинет перенаправляет в свой, чужое действие API возвращает 403, запрос без сессии — 401.
- Сессия хранится в HttpOnly cookie на 8 часов, в HTTPS используется Secure. В БД хранится хеш токена, при выходе сессия удаляется.
- Переводы сотрудником от имени клиента не разрешены. Клиенту недоступны реестр, журнал сотрудника, перемотка времени и сброс демо.
- Баланс, защитная пауза, операции, обращения и реестр находятся на сервере. Старые данные localStorage не импортируются и не используются.

## Сценарий показа

В **Профиле** клиент задаёт лимит одной операции и логины доверенных лиц, выбирает «один» или «все». Операция выше лимита ждёт разрешения из их отдельных аккаунтов в разделе **Подтверждения**, а затем отдельного подтверждения владельца. Повышение лимита/смена группы/отключение защиты требуют старую группу; банковские ограничения не отменяются. По умолчанию функция выключена. [Сценарий и ограничения](docs/trusted-approval.md).

1. Войти как `client`, открыть «Безопасность» и изменить номер телефона. Начнётся 24-часовая пауза.
2. Перевести деньги маме: перевод разрешён после проверки и подтверждения.
3. Попытаться перевести продавцу велосипеда или снять наличные: операция остановлена, списания нет.
4. Открыть обращение по остановленной операции.
5. Выйти и войти как `employee`. Ответить на обращение, проверить журнал и реестр.
6. Выйти и войти как `client`: ответ доступен в личной истории, пауза продолжает действовать.
7. Под сотрудником можно перемотать 24 часа для показа истечения паузы. Остановленные операции автоматически не исполняются.

Cookie действует на весь профиль браузера: для одновременного входа под двумя аккаунтами используйте разные профили или обычное и приватное окно. Кабинеты получают данные из общей БД и обновляются каждые 4 секунды.

## «Это был не я»: старые сессии

- Новый вход клиента, смена телефона или восстановление доступа создают серверное событие безопасности.
- Предупреждение и кнопка доступны только в другой клиентской сессии, начатой строго до события. В сессии-источнике и сессиях, открытых позже события, кнопки нет; прямой запрос API также запрещён.
- Для определения начала используется серверное время истечения сессии минус фиксированные 8 часов: срок сессий не продлевается. Демонстрационная перемотка времени не влияет на возраст сессии.
- Нажатие с подтверждением сохраняет блокировку всех переводов и наличных, завершает другие клиентские сессии и создаёт срочное обращение, видимое сотруднику. История и баланс доступны.
- Блокировка проверяется повторно при подтверждении платежа. Истечение 24 часов, новый вход и ответ сотрудника её не снимают. Отдельного банковского процесса разблокировки в прототипе нет; для нового показа сотрудник использует «Начать заново», сбрасывая демо.
- Проверка: открыть клиента в браузере A, затем того же клиента в отдельном браузере/профиле B. Через 4 секунды в A появится предупреждение о новом входе, а в B — нет. Можно также изменить телефон в B и сообщить об этом из A. Две обычные вкладки одного профиля делят cookie и не считаются независимыми сессиями.

## Локальный запуск

Раздел «Ссылки» использует настоящую URL-модель из репозитория команды, перенесённую на сервер сайта без переобучения. Python-сервис и Groq для неё не нужны. Контракт и проверка эквивалентности: [docs/url-phishing-integration.md](docs/url-phishing-integration.md).

Подробная проверка загружает публичный HTML, изучает формы, перенаправления, название бренда и показывает основания. Без выполнения чужого JavaScript; есть честно помеченные демо-примеры. [Описание сканера](docs/page-inspector.md).

Для живой проверки по умолчанию используется фиксированный Cloudflare DNS-over-HTTPS (без изменения DNS/VPN компьютера), затем ограниченная HTTPS-загрузка и разбор HTML в отдельном Chrome/Edge/Chromium через Playwright Core. Это статический браузерный разбор без JavaScript/ресурсов страницы. Нужен установленный браузер; альтернативный режим без него — `SCANNER_LOADER=static` в `.env`. Настройки приведены в `.env.example` и описании сканера.

Клиенту в «Ссылках» доступны одно поле и одна кнопка; подробности результата раскрываются по желанию. Отдельный экран `/client#jury` («Демо для жюри») содержит четыре примера без сети: подмена банка, поддельный магазин, обычный магазин и недоступная страница. Там же есть дополнительная диагностика модели. Результаты примеров не смешиваются с живыми проверками `/client#links`.

В разделе «QR-коды» (`/client#qr`) можно загрузить PNG/JPEG или вставить текст из QR. Разбор выполняется в браузере: СБП, привязка счёта, реквизиты квитанции, обычная ссылка или фискальный чек. Можно сравнить сумму и имя с ожидаемыми; данные не считаются подтверждёнными банком. Ничего не оплачивается и не открывается автоматически. Четыре вымышленных примера с PNG для жюри — `/client#qr-demo`. [Описание и ограничения QR-проверки](docs/qr-checker.md).

Теперь на экране QR для жюри шесть примеров: добавлены два кода учебного банковского адаптера. Только они по отдельной кнопке разрешаются сервером в канонического получателя и проходят обычную проверку общего реестра/классификатора/паузы. Списание возможно лишь после отдельного подтверждения; неизвестные реальные QR не разрешаются в получателя. [QR → получатель → перевод](docs/qr-payment-bridge.md).

В «Ссылках» добавлена независимая проверка инвестиционного домена по настоящему открытому списку Банка России. Сервер скачивает официальный JSON и сравнивает домен локально, не открывая введённый сайт и не отправляя его URL в ЦБ. Отсутствие записи не означает безопасность. [Источник, кэш и ограничения](docs/cbr-warning-list.md).

У выполненных переводов в истории появилась кнопка «Сообщить об обмане». В `/client#complaints` Qwen уточняет обстоятельства; без ИИ жалобу также можно передать. Сотрудник в `/employee#complaints` назначает дополнительную проверку следующих переводов, включает получателя в стоп-лист демо или закрывает жалобу. Qwen сам реестр не меняет. [Описание и сценарий проверки жалоб](docs/recipient-complaints.md).

Контракт трёх классов, приоритет ограничений, серверная заглушка и проверка сотрудником описаны в [docs/transfer-classification.md](docs/transfer-classification.md).

Сотрудник выбирает клиента в выпадающем списке. «Подробнее» у операции открывает единую карточку: источник платежа, класс/правило защиты, решение сотрудника, привязанный Qwen-диалог и общая сводка жалоб без раскрытия чужого текста. Общий реестр и баланс защищены также от гонки «другой клиент получил отметку между проверкой и списанием». [Проверка новых возможностей и сценарий жюри](docs/shared-protection-demo.md).

Нужен Node.js 22.13 или новее. После скачивания проекта на другой компьютер установите библиотеки командой `npm ci --ignore-scripts` (в текущей копии уже установлены). Сборка, Python и Cloudflare для самостоятельного режима не нужны.

```powershell
npm start
```

Открыть `http://127.0.0.1:3000`. База `data/antiscam.sqlite` и таблицы создаются автоматически. Ctrl+C — остановка. Другой порт: `npm start -- --port 4173`. Разработка: `npm run dev`.

Локальные данные отдельные: облачная D1 и прежняя `.wrangler/state` не импортируются, не удаляются и не синхронизируются. Перенос, настройки `.env`, резервное копирование и границы готовности к обычному серверу: [docs/local-server.md](docs/local-server.md).

Облачные команды сохранены отдельно: `npm run dev:sites`, `npm run start:sites`. Для них нужны зависимости и сборка; локальный режим не публикует сайт.

## Проверки

ИИ-помощник подключён к Groq (Qwen) на сервере. Настройка, ограничения и сценарий демонстрации: [docs/anti-scam-assistant.md](docs/anti-scam-assistant.md).

```powershell
npm test
```

Проверяются права, учётные записи и хеши, неправильный пароль, выход и истечение сессии, защита от подмены роли, серверные ограничения, реестр, обращения и повторное подтверждение.

## Основные файлы

- `lib/bank-api.mjs` — авторизация, API и серверная проверка прав.
- `lib/bank-engine.mjs` — правила переводов и 24-часовой паузы.
- `lib/accounts-seed.mjs` — две роли и хеши четырёх демонстрационных аккаунтов, только сервер.
- `lib/registry-seed.json` — пять вымышленных получателей, только сервер.
- `db/schema.ts` и `drizzle/` — схема и миграции БД.
- `public/app.mjs` — интерфейс кабинетов без клиентского хранилища банковских данных.

Дополнительная защита: [скользящий лимит за 24 часа](docs/rolling-limit.md), [связанная проверка покупки](docs/purchase-check.md) и [учебное восстановление после тревоги](docs/security-recovery.md). [Короткие сценарии проверки](docs/new-protection-demo.md).

Все деньги и получатели демонстрационные. Правило 24 часов — политика прототипа. Банковские сервисы ВТБ и закрытая антифрод-база ЦБ не подключены; открытый список предупреждений ЦБ проверяется отдельно.
