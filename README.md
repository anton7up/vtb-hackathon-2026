# АнтиСкам

Рабочий браузерный прототип для хакатона. Статический сайт без внешних библиотек и банковских интеграций.

## Запуск

В папке `antiscam-demo` выполните:

```powershell
node server.mjs
```

Откройте http://127.0.0.1:4173/. Нужен Node.js 18 или новее. Установка пакетов не требуется. Открывайте через HTTP-сервер, а не двойным щелчком по HTML: модули и JSON загружаются по HTTP.

## Сценарий показа

1. В кабинете клиента нажмите «Сменить номер» и сохраните предложенный вымышленный номер. Начнётся 24-часовая пауза.
2. Переведите 3 000 ₽ получателю «Мама». Проверка и подтверждение доступны, баланс уменьшается только после подтверждения.
3. Выберите «Продавец велосипеда» и попробуйте перевести деньги. Новый получатель остановлен, баланс не меняется.
4. Переключитесь на «Наличные». Снятие также остановлено.
5. Выберите «Демо получатель 2»: этому получателю переводили в прошлом, но теперь он в реестре. Перевод остановится по реестру.
6. У остановленной операции нажмите «Обратиться в банк». Переключитесь на «Сотрудник банка», ответьте на обращение. Вернитесь в историю клиента: ответ уже там, пауза всё ещё действует.
7. Нажмите «Перемотать 24 часа». Новый безопасный получатель и наличные доступны. Перевод получателю из реестра всё ещё остановлен. Ранее остановленные попытки не отправляются автоматически.
8. В кабинете сотрудника откройте «Реестр» и добавьте `DEMO-NEW-001`. Теперь продавец велосипеда также блокируется реестром.

## Две вкладки

Клиент: http://127.0.0.1:4173/?role=client

Сотрудник: http://127.0.0.1:4173/?role=employee

Откройте обе ссылки в одном профиле браузера. localStorage хранит общее состояние, событие storage обновляет вторую вкладку. Web Locks сериализует изменения, где API доступен. Перезагрузка сохраняет данные и таймер. Отдельные устройства и профили браузера не синхронизируются. Переключатель ролей демонстрационный, реальной авторизации нет.

## Что реализовано

- 24-часовая пауза после смены номера или восстановления доступа.
- Успешные переводы до изменения данных определяют прежних получателей по ID.
- Во время паузы новые получатели и наличные остановлены, старые проверяются по реестру.
- Активная запись реестра имеет приоритет над историей и таймером.
- Если JSON-реестр недоступен, переводы остаются на проверке без списания.
- Повторная проверка на шаге подтверждения; защита от двойного подтверждения.
- Расчёты в копейках, проверка ввода и доступного баланса.
- История, обращения, ответы сотрудника, добавление вымышленных записей в реестр, журнал.
- Метрики считаются по действиям в текущей демонстрации; сумма остановленных попыток не объявляется сохранёнными деньгами.

## Файлы

- `dist/engine.mjs` — правила и операции.
- `dist/app.mjs` — интерфейс и браузерное состояние.
- `dist/data/suspicious_recipients.json` — пять начальных синтетических записей.
- `tests/engine.test.mjs` — проверки правил.

```powershell
node --test tests/engine.test.mjs
```

Для настоящего банковского продукта проверка, время, авторизация и хранение должны находиться на сервере. Текущее правило 24 часов — политика демо, не формулировка требования закона. Все данные вымышлены, подключения к базе Банка России нет.
