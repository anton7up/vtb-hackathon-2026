# ИИ-помощник антифрода

Это реальная интеграция с Groq Chat Completions, модель `qwen/qwen3.8-27b`, а не заглушка. Классификатор транзакционных признаков — отдельная обученная Python-модель; Groq не заменяет её и не присваивает исходный класс перевода. Помощник анализирует рассказ клиента и задаёт уточняющие вопросы (не более четырёх ответов клиента).

## Сценарий показа

1. При попытке перевода с классом `review` открывается обычное окно результата: перевод поставлен на дополнительную проверку, деньги не списаны. В нём есть отдельная заметная кнопка «Перейти к проверке с ИИ»; переход не происходит автоматически. Операция также появляется в разделе «Безопасность» → «Переводы на дополнительной проверке», где ИИ-диалог можно открыть повторно. Отдельный раздел «ИИ-помощник» по-прежнему доступен для общих консультаций.
2. Вводит вымышленную ситуацию и подтверждает согласие на передачу текста Groq и сохранение для сотрудника.
3. Пример: «Мне позвонил человек, представился сотрудником МВД и велел срочно перевести деньги на безопасный счёт». Помощник определяет схему и объясняет риск.
4. Сотрудник видит переписку и вывод в разделе операций. Общая консультация не связана с переводом и сама по себе его не блокирует.

Приветствие с именем формируется интерфейсом, имя из аккаунта в Groq не передаётся. Открытие окна само по себе не вызывает API модели: нужен текст клиента и согласие. Для одного перевода повторно открывается его сохранённый диалог, а не создаётся общая консультация. Окно отражает блокировку, завершение или одобрение сотрудником. После одобрения доступно отдельное подтверждение клиентом; закрытие окна не отправляет деньги и не снимает проверку.

## Три класса

- `normal`: явная схема не выявлена; не является гарантией безопасности, разрешением сотрудника или командой списания.
- `review`: нужны уточнения либо проверка сотрудника; пока есть уточняющий вопрос, класс всегда `review`.
- `block`: обнаружена схема с дословным подтверждением в сообщении. Если диалог связан с ожидающей проверки операцией, она блокируется без списания. Не блокирует весь счёт.

Схемы: безопасный счёт, давление от имени правоохранительных органов, фишинг и коды, удалённый доступ, подмена знакомого, инвестиционное мошенничество, кредит под давлением, курьер/снятие наличных. Текст клиента считается недоверенными данными, а не инструкцией модели.

## Защита

- Ключ `GROQ_API_KEY` только на сервере; в Sites используется runtime secret. Локальный `.env` исключён из Git. Не используйте префиксы публичных переменных.
- В модель передаются только реплики, предыдущие вопросы и минимальный контекст: сумма, новый ли получатель, класс операции. Не передаются учётная запись, баланс, весь журнал или реквизиты получателя.
- Из текста маскируются распространённые форматы телефонов, карт, email, ссылок, кодов и ключей. Это не полная анонимизация: вводить настоящие персональные данные нельзя.
- JSON модели проверяется сервером: допустимые классы, длины, список сценариев, дословность цитат. Для `review` недословные цитаты удаляются, а уточняющий вопрос сохраняется. Для `block` и `normal` недословная цитата отклоняет ответ; для блокировки обязательно хотя бы одно дословное основание. Некорректные типы и длины по-прежнему отклоняются. Ошибочный JSON не превращается в одобрение.
- Помощник не имеет платёжных инструментов. Одобрение сотрудником и подтверждение клиентом остаются отдельными действиями. Во время анализа связанной операции одобрение запрещено; прежнее одобрение отзывается.
- Запросы идемпотентны по идентификатору. Сброс демо во время ответа не восстанавливает старое состояние. Изменения сохраняются с проверкой версии состояния.
- Лимит приложения: 4 новых запроса в минуту и 60 в сутки на клиентский аккаунт (общий демо-аккаунт делит лимит). У Groq есть дополнительные ограничения. Ошибки, квота, отсутствие ключа и таймаут не одобряют перевод. Автоматического платного резервного провайдера нет.
- До 1200 символов на реплику, до четырёх ответов на диалог. API ждёт ответ не более 25 секунд суммарно. Только при ошибке генерации JSON у Groq разрешена одна повторная попытка к той же модели; она также расходует квоту провайдера. Отклонённый ответ не используется.

Проверки: `node --test tests/auth.test.mjs tests/engine.test.mjs tests/assistant.test.mjs tests/review-assistant.test.mjs`. В тестах API подменён; отдельно проверен настоящий вызов Groq на синтетическом примере. Автоматическое открытие окна и сохранение баланса при закрытии проверены в локальном браузере. Реальных банковских данных и интеграции с ВТБ нет.
