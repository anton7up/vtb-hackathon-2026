# Локальная система и последующий перенос на сервер

Основной режим разработки — самостоятельный Node.js HTTP-сервер с SQLite, а не публикация в Sites. Клиент, сотрудник, серверная авторизация, защитная пауза, реестр, обращения, классы переводов и URL-модель используют прежнюю логику. Cloudflare, ChatGPT-вход и доступ к домену для запуска не требуются. Изменения в локальном проекте не публикуются автоматически.

## Запустить на компьютере

Нужен Node.js 22.13+ (проверено на 22.21.0). Используется встроенный `node:sqlite`: в Node 22 возможен `ExperimentalWarning`, это не ошибка запуска. Сборка React/Vinext для самостоятельного режима не нужна. HTML-сканер использует npm-библиотеки parse5, tldts и ipaddr.js: в этой рабочей копии они уже установлены; после скачивания проекта на другой компьютер выполните `npm ci --ignore-scripts` один раз.

В Windows, из папки проекта:

```powershell
cd "C:\Users\Asus\Desktop\хакатон втб\antiscam-demo"
npm start
```

Открыть `http://127.0.0.1:3000`. Окно терминала должно оставаться открытым. Остановить — Ctrl+C. Если порт занят: `npm start -- --port 4173`.

`npm run dev` запускает тот же сервер с перезапуском при изменении серверного JS. После изменения файлов интерфейса обновите страницу браузера. Основные файлы интерфейса: `public/app.mjs`, `public/review-assistant.mjs`, `public/style.css`. Оболочки локальных страниц — `server/pages.mjs`; облачные React-оболочки в `app/` сохранены отдельно. Изменяя структуру оболочек, синхронизируйте обе версии; бизнес-логика API и JS-интерфейс общие.

Войти учебными аккаунтами `client`, `client2`, `client3` или `employee`, пароли переданы владельцу. Клиентов трое с раздельными банковскими состояниями, ролей по-прежнему две. Сотрудник выбирает просматриваемого клиента; реестр получателей общий. Для одновременной работы используйте разные профили браузера или обычное/приватное окно: вкладки одного профиля делят cookie. Сотрудник не может выполнять перевод от лица клиента, роль проверяется сервером. В профиле можно включить подтверждение крупных операций доверенными лицами, подробности в `docs/trusted-approval.md`.

## Где база

По умолчанию — `data/antiscam.sqlite`, рядом могут появиться `-wal` и `-shm`. База, таблицы и четыре демо-аккаунта создаются автоматически; ручная миграция не требуется. Миграции `drizzle/*.sql` применяются один раз, с контролем checksum; уже применённые SQL не редактируйте, добавляйте новые. Миграция `0001_shared_complaints.sql` добавляет общий индекс обращений; прежние данные не сбрасываются. Настройки доверенных лиц сохраняются в состоянии клиента без новой SQL-миграции.

Это **отдельная локальная база**, не копия облачной D1 и не импорт старой `.wrangler/state`. Данные в существующих базах не удаляются и не изменяются. История, баланс, обращения и сессии самостоятельного режима сохраняются после остановки и повторного запуска. Они не синхронизируются с публичным демо.

Файл БД и `.env` не отправлять в Git. Другая папка задаётся `DATABASE_PATH` (относительный путь считается от корня проекта). Для резервной копии остановите сервер и скопируйте **всю папку data**, не только основной файл работающей WAL-базы. При переносе сохраните резервную копию до первого запуска на новом месте. Для параллельно работающей системы нужен отдельный процесс согласованных резервных копий.

## Модели и интернет

* Проверка URL: `lib/url-phishing-model.mjs` + `lib/phishing-model.json`, вычисляется здесь же, без Python, Groq или интернета. Страницы по введённым адресам не открываются. Модель анализирует только строку, ошибается и не доказывает мошенничество; перенос весов описан в `docs/url-phishing-integration.md`.
* Подробная проверка страницы: `server/scanner/`, требует интернет для живого адреса, но не Groq/ИИ-ключ. Анализирует загруженный HTML без исполнения JavaScript. Подробности и пределы MVP: `docs/page-inspector.md`. Демо-сценарии работают без сети и помечены отдельно.
* Классификатор переводов: пока серверная заглушка с тремя классами. Проверка URL не заменяет модель переводов.
* Диалоговый помощник: внешний Groq/Qwen, требует интернет и `GROQ_API_KEY`. При отсутствии ключа сайт и URL-модель работают, помощник сообщает, что не настроен. Сбой ИИ не разрешает платёж автоматически.

Можно скопировать `.env.example` в `.env` и заполнить нужные значения. Существующий `.env` не перезаписывайте. Сервер читает `.env` при старте; после изменения перезапустите его. Значения окружения процесса имеют приоритет. Реальные ключи в исходники, публичные файлы или переписку не вставлять.

## Перенос на обычный сервер — следующий этап

Для самостоятельного режима не нужен Cloudflare-адаптер. Переносятся исходники (включая `server`, `lib`, `public`, `app/globals.css`, `drizzle`) и отдельно резервная копия локальной БД. На сервере нужен совместимый Node.js. Для этого пути `npm run build` не требуется; команда запуска та же — `npm start`. SQLite — один узел с постоянным локальным диском; не размещайте файл в Git, ephemeral storage или общей сетевой папке. Для нескольких серверных реплик понадобится другая СУБД/архитектура.

Перед внешним размещением нужны HTTPS reverse proxy, автозапуск сервиса, отдельный системный пользователь, резервные копии, закрытый от сети порт backend и замена общих демонстрационных учётных данных безопасным процессом управления аккаунтами. Не используйте прототип для настоящих денег/банковских данных.

За reverse proxy, например:

```dotenv
HOST=127.0.0.1
PORT=3000
PUBLIC_ORIGIN=https://your-domain.example
DATABASE_PATH=/var/lib/antiscam/antiscam.sqlite
```

Здесь домен — заглушка, его нужно заменить своим. Proxy передаёт исходный `Host`, проксирует UI и `/api/` на один backend. Сервер берёт публичную схему из явного `PUBLIC_ORIGIN`, а не из произвольного `X-Forwarded-Proto`; HTTPS-сессии получают Secure cookie. Не включайте HTTPS-origin при прямом тестировании по HTTP: браузер не будет отправлять такую Secure cookie. Не доверяем входному `CF-Connecting-IP`/`X-Forwarded-For`: login quota использует адрес непосредственного соединения. За proxy лимит входов разделяется между пользователями proxy; корректный trusted-proxy rate limit — отдельная серверная настройка, а не доверие любому заголовку.

По умолчанию сервер доступен только на этом компьютере. Для прослушивания не-loopback адреса обязательно явно задать `PUBLIC_ORIGIN`; открытие доступа в локальную сеть/интернет и настройка TLS в эту работу не включены.

## Проверить

```powershell
npm test
```

Проверки включают реальный Node HTTP + SQLite, доступ по ролям, CSRF, закрытые файлы, модель, транзакционный rollback, повторное применение миграций, сохранение состояния и сессии после перезапуска. `GET /healthz` возвращает только `{ "ok": true }`, без секретов или банковских данных.

## Сохранённый облачный режим

Он не является обязательной частью локальной системы. Старые команды доступны как `npm run dev:sites` и `npm run start:sites`; для них по-прежнему нужны npm-зависимости, сборка и Wrangler/D1. `.openai/hosting.json` и исходный идентификатор Sites сохранены. Публичная версия не меняется от `npm start` и не использует `data/antiscam.sqlite`.
