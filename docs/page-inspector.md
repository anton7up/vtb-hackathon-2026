# Подробная проверка страницы — локальный MVP

Клиентский раздел «Ссылки» — одна строка адреса и одна кнопка **«Проверить ссылку»**. Можно вставить домен без `https://`: интерфейс добавит его сам. Проверка загружает публичный HTML, анализирует его правилами и учитывает отдельный сигнал URL-модели. Это не новая обученная HTML-модель и не гарантия отсутствия мошенничества.

Сначала показываются короткий вывод, совет и до трёх причин. Формы, цепочка переходов, ограничения и технические сигналы спрятаны в закрытый блок «Подробнее о проверке».

**«Демо для жюри»** вынесено на отдельный экран: `/client#jury` (обычная проверка — `/client#links`). В нём четыре сценария без сети и закрытая дополнительная диагностика URL-модели TF-IDF + LogisticRegression. Демо и живая проверка используют раздельные поля ввода, состояние загрузки и результаты: учебный отчёт не появляется как результат реального адреса. Это отдельный экран показа, а не новая роль или обход авторизации.

Доступно в кабинетах клиента и сотрудника. Работает в самостоятельном Node-сервере (`npm start`), без Groq, Python и облачного хостинга Sites. По умолчанию используется ограниченная HTTPS-загрузка с Cloudflare DNS-over-HTTPS и затем **браузерный разбор статического HTML** в установленном Chrome/Edge/Chromium через Playwright Core. Это не динамическая отрисовка: JavaScript и загрузка ресурсов проверяемой страницы отключены. Cloudflare Workers-режим получает `websiteInspector.configured = false`, не пытается выполнять Node-сканер и не подменяет его URL-проверкой. Изменения не публиковались.

## Запуск и проверка

В текущей рабочей копии зависимости уже установлены. После скачивания обновлённого проекта на другой компьютер сначала выполните `npm ci --ignore-scripts`, затем `npm start` (Node.js 22.13+). Для старого режима Sites используйте его отдельную инструкцию сборки/установки.

Если сервер запущен через `npm start`, остановите его Ctrl+C и запустите повторно, затем обновите браузер. `npm run dev` отслеживает импортируемые серверные файлы автоматически. Не публикуйте `.env`, `data/` и локальную БД в Git.

Для живого адреса вставьте публичный HTTP(S)-URL или домен и нажмите «Проверить ссылку». Под кнопкой объяснено, что нажатие разрешает загрузку страницы: сайт увидит IP сканера (при локальной работе — внешний адрес подключения компьютера), а домен может передаваться в Cloudflare DNS. DNS получает только домен, не полный URL, HTML, cookies или банковские данные. Отдельного чекбокса и выбора режима нет. Не вставляйте секретные ссылки, токены и персональные данные. При редактировании адреса прежний отчёт сбрасывается; новая загрузка выполняется только после повторного нажатия.

В текущем сетевом окружении системный DNS возвращал служебные IP `198.18.x.x` вместо публичных (характерно для VPN/прокси в режиме Fake-IP). Для режима `SCANNER_DNS=system` это по-прежнему означает `non_public_dns`. Диапазон не добавлен в исключения: вместо этого новый режим `cloudflare` обращается к фиксированному HTTPS DNS endpoint с закреплённым публичным bootstrap IP и обычной проверкой TLS. Все адреса A/AAAA и переходы затем проходят прежнюю проверку публичности и pin соединения. Нет системного DNS fallback и пользовательского URL резолвера. Настройки DNS/VPN компьютера не изменяются.

30.10.2026 подтверждена реальная загрузка `https://example.com/`: `source=live`, `status=completed`, HTTP 200, 577 байт исходного HTML, заголовок «Example Domain», `retrieval.loader=browser_static`. Это не фикстура. URL-модель на этом адресе выдала предупреждение: успешная загрузка страницы не подтверждает точность модели и не превращает её оценку в доказательство мошенничества.

Настройки сервера в `.env` (после изменения перезапустите `npm start`):

* `SCANNER_LOADER=browser` — реальная ограниченная загрузка плюс offline-разбор в отдельном Chromium без выполнения JS. Нужен установленный Chrome/Edge/Chromium; личный профиль не открывается.
* `SCANNER_LOADER=static` — прежний parse5-анализ, без запуска браузера.
* `SCANNER_DNS=cloudflare` — фиксированный DNS-over-HTTPS, только для сканера (по умолчанию).
* `SCANNER_DNS=system` — системный DNS с прежней блокировкой Fake-IP/служебных адресов.
* `SCANNER_BROWSER_PATH` — необязательный абсолютный путь к установленному браузеру. Без него проверяются обычные системные пути Chrome/Edge/Chromium. Новый браузер автоматически не скачивается.

Для показа без сети откройте «Демо для жюри» и выберите один из четырёх сценариев: подмена банка, поддельный магазин, обычный магазин или невозможность проверки из-за CAPTCHA. Они обрабатывают сохранённый синтетический HTML, явно помечаются **учебными примерами без сети**, никогда не обращаются к банку/магазину и не подменяют результаты живой проверки.

«Поддельный магазин» (`shop_clone`) — вымышленная страница `https://ozon-sale.example/checkout`: представляется официальным магазином Ozon, просит номер карты, CVV/CVC и SMS-код, а в HTML-форме заявляет отправку на `collector.example`. Реальные страницы Ozon не загружаются. Обычный анализатор, без специальной подстановки вердикта, получает сочетание несовпадения домена, заявления об официальности и внешней отправки чувствительных полей: `high_risk`. В клиентском выводе — «Есть признаки обмана», совет не вводить данные и причины. Наличие бренда или платёжной формы по отдельности не считается доказательством подделки; визуальное сравнение дизайна не добавлено.

## Что реализовано

* HTTP GET одной страницы, до 4 HTTP-перенаправлений; конечный домен и цепочка переходов.
* Проверка сертификата HTTPS стандартным клиентом Node; ошибки сертификата не обходятся. HTTPS сам по себе не доказывает честность сайта.
* Ограниченная загрузка исходного HTML; в режиме `browser` — затем отдельный sandboxed headless Chromium, fresh context `offline`, `javaScriptEnabled=false`, `serviceWorkers=block`, запрет downloads, CSP `default-src 'none'`. Ровно один main-frame GET получает уже скачанный HTML через `route.fulfill`; остальные запросы документа блокируются. Chromium не используется как обход сетевой политики и не подключается к проверяемому серверу сам.
* HTML5-анализ через parse5, без выполнения кода, без загрузки изображений, CSS, скриптов, iframe и других подресурсов страницы. Динамический JS-контент не исследуется.
* Заголовок, H1, `og:site_name`, текстовые `alt` первых изображений; сопоставление упомянутого бренда с небольшим неполным справочником. Нет визуального распознавания логотипов.
* Поля пароля, карты, CVV/CVC и кода подтверждения, в том числе по autocomplete/подписям; поля вне формы с атрибутом `form`.
* Заявленные `action`, метод формы, `base`, некоторые `formaction` кнопок; HTTP, GET с чувствительными полями и отправка на другой домен. Домен определяется по Public Suffix List (tldts), а не по двум последним сегментам строки.
* Простые текстовые сигналы: «безопасный счёт», требования отключить защиту/установить удалённый доступ, упоминание перевода частному лицу. Цитата такой фразы в учебной статье может дать предупреждение: контекст требует проверки.
* Упоминания контактов, доставки, возврата и реквизитов компании — без проверки подлинности, без вывода о недобросовестности только из-за отсутствия текста.
* Объявленный meta refresh отмечается, но не выполняется. CAPTCHA, короткая JS-оболочка, ошибки сети и лимитов дают незавершённую проверку.

Детали — максимум первых 12 форм, 30 000 HTML-узлов и 60 000 символов текста. Скрытые атрибутом `hidden`/inline CSS элементы и содержимое script/style/template не используются как текстовые основания. Это не точное вычисление видимости браузером; например, внешние CSS не загружаются.

## Результат и API

`POST /api/phishing/inspect` с существующей сессией и same-origin проверкой:

```json
{"url":"https://example.com/","consent":true}
```

Демо вместо живого адреса:

```json
{"demoScenario":"brand_clone"}
```

Ответ `report` содержит `status`, `verdict`, `source`, `checked_at`, `findings` с причинами, `forms`, `brands`, `redirects`, `shop`, отдельный `ml` и `limitations`. У завершённых живых проверок есть `retrieval` с `loader` (`browser_static` или `static`), `dns`, `javascript_executed=false` и `subresources_loaded=false`. Исходный объём сетевого HTML остаётся в `summary.html_bytes`; DOM отдельно ограничивается тем же пределом. Это не доказательство исполнения JavaScript или проверки всех страниц сайта.

* `completed + high_risk`: сильный сигнал (например, чувствительная форма по HTTP либо сочетание подмены бренда и запроса банковского пароля).
* `completed + review`: есть замечания, включая самостоятельное предупреждение URL-модели. У модели бывают ложные срабатывания, в том числе на example.com.
* `completed + no_signals`: в пределах проведённых проверок признаки не найдены, не «сайт безопасен».
* `unavailable + null`: проверка страницы не выполнена/недостаточно HTML. Никогда не заменяется положительным классом.

Это правила приоритета сигналов, **не откалиброванная вероятность** и не модель классов банковских переводов. Совпадение известного домена или платёжного сервиса не является безусловным пропуском. Сканер не изменяет счёт, реестр, операции, защитную паузу или решения сотрудника.

## Минимальные ограничения безопасности

Выполнение — в одноразовом дочернем процессе Node (до 128 MB heap), без наследования `.env`, Groq-ключа, cookie и дескрипторов банковской БД. Передаются только системные `SystemRoot/TEMP/TMP`, URL/имя фиксированного демо и серверные параметры режима. Это **разделение процессов, а не полноценная ОС-песочница**: процесс технически работает под тем же системным пользователем. Браузер запускается с включённым Chromium sandbox, новым временным профилем и минимальным окружением; личный профиль не используется. Лимит Node heap не ограничивает память Chromium.

Браузер закрывается в `finally`, при отмене и дедлайне. Родитель пытается завершить дерево процесса на Windows и выделенную группу на POSIX. Это best-effort: аварийный выход родителя на Windows не даёт строгой гарантии уборки потомков без Job Object/контейнера. Offline/routes/CSP ограничивают документ, а не заменяют системный egress firewall и не доказывают отсутствие всего фонового трафика самого браузера. Промышленная изоляция, контейнер/VM, ограничения памяти/дерева процессов и egress firewall остаются следующим этапом. Для этого MVP не запускается чужой JavaScript и не принимаются пользовательские плагины/код.

Сетевые ограничения не отключены даже в хакатоне:

* Только HTTP:80 / HTTPS:443, без userinfo, специальных доменов и внутренних/special IPv4/IPv6.
* Все полученные DNS-адреса должны быть публичными; адрес подключения закрепляется за проверенным IP (с исходным hostname для Host/TLS), без повторного неконтролируемого DNS-разрешения.
* Фактический адрес соединения дополнительно проверяется; каждый HTTP-редирект проходит ту же политику.
* Cookies, Authorization и произвольные пользовательские заголовки не передаются. Автозагрузки, POST/формы и обход CAPTCHA не выполняются.
* Исходный HTML и браузерный DOM независимо ограничены 768 KiB, заголовки сайта — 16 KiB; до 12 секунд сетевой работы, до 8 секунд браузерного этапа, 28 секунд до принудительного завершения worker, 2 процесса одновременно, 6 проверок в минуту на аккаунт. Используется Accept-Encoding: identity; неожиданное сжатие пока приводит к «не удалось проверить», а не неограниченной распаковке.
* DoH: только фиксированный `cloudflare-dns.com/dns-query` через `1.1.1.1`, без HTTP-редиректов и смены TLS hostname; ответ до 32 KiB, заголовки до 8 KiB, ограниченная CNAME-цепочка. Непубличный адрес даже среди остальных ответов отклоняется.

HTML и отчёты не записываются в банковскую БД/историю; сохраняется только хешированный ключ счётчика лимита. Из показываемых сетевых адресов удаляются query и fragment, но секреты могут находиться и в пути — не используйте приватные URL. Чужие строки выводятся экранированным текстом, не как HTML и не как автоматически открываемые ссылки.

## Что пока не сделано

Полноценный обход всех страниц сайта, динамическая отрисовка с выполнением чужого JavaScript, скриншоты/OCR, логотипы по изображению, возраст домена/RDAP, Google Safe Browsing и другие внешние базы, проверка доставки или юридической принадлежности. QR реализован отдельным [локальным модулем](qr-checker.md), не HTML-сканером. Отправка формы не наблюдалась, поэтому report показывает **заявленный**, а не гарантированный фактический адрес передачи данных.

## Источники и сопровождение справочника

`server/scanner/brands.json` содержит источники и версию. Выбранные банковские домены сверены с [публикацией Банка России](https://www.cbr.ru/banking_sector/credit/cowebsites/), магазины — с публичными официальными страницами [Ozon](https://www.ozon.ru/), [Wildberries](https://www.wildberries.ru/), [adidas](https://www.adidas.com/). Это выборка для демонстрации, не полный реестр всех доменов организаций. Платёжный справочник ограничен доменами из документации [ЮKassa](https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process) и [CloudPayments](https://developers.cloudpayments.ru/).

Рекомендации по сетевому ограничению: [OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). При добавлении браузерного этапа отдельно проектируйте изоляцию, а не включайте выполнение чужого JS внутри банковского сервера.

Проверки: `npm test`. Есть сетевые unit-тесты без обращений к опасным сайтам, разбор синтетического HTML, экранирование отчёта, worker-демо и HTTP-проверки авторизации/согласия/квоты/неизменности банковских данных.

Дополнительно выполнен настоящий offline smoke установленного Chromium: `node tests/browser-offline.smoke.mjs`. Подготовленный документ с inline script, img, iframe и meta refresh разобран без выполнения скрипта (заголовок остался «Static smoke OK»), обработчик завершился и закрыл браузер. Этот скрипт запускается явно, не входит в `npm test` и не скачивает проверяемые сайты. Он не доказывает полноценную ОС-изоляцию браузера.

Документация технологий: [Playwright Browser contexts](https://playwright.dev/docs/api/class-browser), [Cloudflare DNS-over-HTTPS API](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/), [рекомендации Playwright для недоверенных сайтов](https://playwright.dev/docs/docker).
